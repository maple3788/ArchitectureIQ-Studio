# 规则发现与迭代

在 Harness 的“切换学习方法”中选择“规则 KB 闭环”。这个方法从 Dataset 出发，用可执行条件规则预测候选优劣，把错题、冲突、未覆盖题和规则反例交给模型提出修改。程序执行规则、封存预测、计算成绩并验收补丁；逐题作答不调用模型。

## 配置和开始

1. 选择 discovery Dataset 的固定修订，使用单题或完整题对。
2. 选择初始研究规则 KB、从空规则开始，或让初始化模型根据公开题目提出规则。正式 KB 会转成独立研究副本。
3. 配置修订模型和附加提示词。画布可添加、移除问题分组，拖动反馈端口或调整分组位置来组织材料。
4. 配置新题方案和运行限制，先“检查运行配置”，再“开始研究”。

“匹配预览”只读取公开题面与规格，不读取答案、不调用模型。界面明确当前分页范围；没有唯一第一名，或者任意候选关系发生冲突或循环时，程序明确拒答。

模型调用次数、累计 token、候选 × 种子执行量和总时长必须填写正上限。真实模型和构题执行受授权服务器门禁约束；本地仍可编辑、匹配、预览和阅读已有结果。编译不完整的画布可以存成共享草稿，但不能启动。

## 闭环如何推进

程序先封存整批预测，再读取存储反馈。候选 KB 必须在同一个累计题池上回归，不能让任何已接受版本答对的题退步。验收依次比较正确题数、冲突数、错误规则断言数和明确作答数；只改说明文字不算规则进步。即使第一名正确，被 GT 否定的下位候选直接关系仍是反例。

当前题池全部通过后才生成新挑战。每批新题先由冻结 KB 首测，保存原始成绩，再把全部有效题目纳入研究池。失败批次也保留，后续修订不能覆盖它的第一次成绩。资料缺失或损坏单独报告，不能算成通过或普通错题。改名、重排候选和同实例换包装不算独立新题。

## 停止条件

| 设置 | 默认值 |
| --- | --- |
| 最大修订尝试 | 12 |
| 连续无进步尝试 | 3 |
| 最大新题生成尝试 | 3 |
| 每批实际题目数 | 16，配对时为 8 对 |
| 累计新题上限 | 48 |
| 同一 KB 连续新批次首测通过目标 | 2 |

达到目标还要求累计研究池全部通过。接受新的 KB 版本会重置连续通过计数；失败、不足或重复批次也不计为通过。调用失败和被拒补丁仍消耗相应预算。部分完成的构题保守保留整个已预留的 GT 工作量；不能确认是否执行的外部调用不会退款后重发。

只有满足目标才显示“目标已达成”。达到预算、无进展、用户停止、执行故障或结果不确定时，仍保存当前最佳 KB、真实成绩和未解决问题。

## 阅读结果和恢复

运行详情分别展示累计研究池成绩、新题原始首测、接受或拒绝的补丁，以及规则直接证据和推导路径。未命中规则显示“尚未检验”；GT 无法判定的候选关系不当作支持或反例。

KB 默认先阅读知识，再切换适用题目。研究规则只说明在已记录条件和批次上的表现，不自动获得正式知识的独立确认状态；不会自动进入原科学/RAG 的正式知识候选列表。

阶段与模型文本来自持久化事件，两个游标分别续接。关闭浏览器不会停止运行，刷新只读取已有状态。暂停在安全边界生效，总时限继续累计。中断后显式“核验并恢复”复用封存产物；结果不确定的外部调用不会自动重发。源码、模型或输入身份变化时应新建运行，不能修改旧指纹继续执行。

## 独立 Task 检查

在 KB 中点击“在 Task 中检查此规则 KB”，或在 Task 的“规则 KB 检查”页选择冻结规则和 development/final Dataset。预览后执行纯规则评测，它不需要模型、不生成新题、不修改 KB，也不把反馈加入原研究池。本地页面可以运行此存储结果检查。

系统检查题目、数据实例、谱系和题对与累计研究及 KB 祖先的重叠。已知重叠或无法核验身份会阻止提交；排队期间研究谱系发生变化也要求重新预览。结果区分“首次使用且可核验”“重复评测”和“此前接触情况未知”。重复使用同一评测集不再视为首次独立检查。

## 验证范围

本次实现以合成题、mock 模型和模拟 GT 边界验证规则执行、验收、预算、恢复、API 与页面。Mock 成绩只用于软件验收，不代表真实模型效果。真实闭环需要在授权服务器上明确选定模型、Dataset 与正数资源上限后另行运行。

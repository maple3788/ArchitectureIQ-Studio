# Workflow Studio

Workflow Studio 是独立的研究界面：`frontend/workflow/` + `services/kb_workflow_api/`。
它读取真实题目、模型配置和运行记录；科学训练仍走现有 spec → code → run → GT 流水线。

## Data 工作空间

默认入口为 **Data · 题库**（`#data`），包含命名 Dataset 和统一去重的总题库。Dataset 可以共享同一道题，移除成员或归档只改变集合，不删除源题、其他集合或历史运行。已有题源和冻结题集在启动时幂等登记为初始 Dataset；后续启动不会覆盖用户编辑。旧 `#questions`、`#generation` 等链接继续可用。

主导航保留 **Datasets / 总题库**，生成任务与题源管理收进“更多”。Dataset 列表以紧凑条目展示，历史研究选集默认收起；搜索仍能找到其中的内容。相同成员集合合组显示，展开后可分别打开每个原集合及其固定修订。该分组不合并存储、不累计重复题数，也不把单题集合与配对集合混为一组。添加题目与管理操作分别集中在两个菜单中。

- **管理题库**：新建空 Dataset，填写研究用途；从总题库跨页选入题目、上传 JSON 题包，或进入分块构题。题目允许暂不满足研究条件，运行前另行检查。
- **总题库**：严格内容等价的完整记录合并展示，保留精确版本、来源和所属 Dataset。相似措辞不自动合并；反馈、数据实例、配置或身份边界不同的题目保持独立。不完整或无法证明等价的审计记录保守分开。
- **阅读题目**：题面、数据规则与候选对比各有阅读层次；可选择候选、用方向键切换，并选两个方案集中比较。阅读选择不会产生答案收据或评分，不会展示私有 GT。
- **构建题目**：按数据规则、候选与比较因素、单题/题对、预算与规模分块配置。参数来自服务端能力清单，右侧仅展示规格和真实预检成本；实际题目由 canonical 流水线生成。普通 Dataset 为空时可接收完整题对并切换为配对模式；非空集合必须匹配生成模式。
- **并发和收录恢复**：修改请求绑定基准修订。冲突时保留选择，可载入最新版本后将自己的增删合并。生成先保存结果，再尝试收录；目标被修改或归档时，从生成记录选择目标 Dataset，使用“将已有结果加入 Dataset”。这一步只处理已持久化题目，不会重跑 GT。
- **接入工作流**：在现有工作流使用“从 Dataset 选择”，固定集合版本后选整套、筛选或按 seed 抽样，预览实际清单再应用。单题学习必须明确选择一道题；题对以完整单元选择，评测仍要求对应 development/final 分区。已应用输入不随 Dataset 后续编辑变化。

[KB 真理闭环](rule-refinement.md) 是 Harness 的主要入口，其他研究方法收进“其他方法”。一张画布说明出题、验证、错题反馈、修订与不退步验收，点击节点才展开配置；运行追踪沿用同一路径，读取已保存的阶段和证据。KB 规则阅读、适用题目和独立 Task 检查继续可用。

## KB 知识库

KB 首页优先展示规则知识库，学习经验和历史材料各自收起，搜索覆盖所有类别。内置 v9、v10 属于同一个“架构与优化器规则”库，默认阅读 v10，并可在库内切换版本。只有明确登记了同一库身份的版本才合组；同名的独立研究记录不会自动合并。Harness 与 Task 始终引用用户选中的原始 `id/version`，页面组织信息不进入冻结快照。

历史知识按原始主张阅读，复合主张的每个规则分支仍分别保留适用条件、验证状态和证据；记录数与主张数分别展示。

## 使用

1. 在**题库**浏览全部已登记来源，按 family、题型、模型架构和题目 ID 检索。点击题目查看公开题面、候选代码、数据来源与完整性问题。选择题目并保存题集后，ID、版本、顺序及配对谱系被冻结。
2. 在**模型**登记 OpenAI-compatible 服务，修改推理参数并检查连接。被测 LLM 与题目候选的 model type 是两个不同概念。API 密钥只填写服务器环境变量名。
3. **工作流**按 Data → Harness → KB → Task 纵向排列。Data 中分类、多选研究题目，Harness 中选择固定模型、研究轮数与角色提示词，KB 展示知识正文、验证状态与适用条件，Task 选择独立新题验证效果。内部 agent 图、实验预算、路径与原始记录按需展开。选题阅读器保留“题目概览 / 数据与规则 / 原始 Prompt”，底部已选列表可以逐题检查或移除。
4. 在**测试运行**选择一个或多个模型，先预览完整公开请求，再提交。每次请求保留最终 HTTP 请求体、哈希、原始服务返回、解析结果、token 用量与评分。服务没有返回的内部状态不会被推测出来。
5. 在**生成任务**配置 profile、family、候选数、训练预算和种子。服务端预检会冻结独立数据实例的 seed plan，并计算总训练次数。通过显著性筛选的题目自动回到题库；不足、失败和未通过的原因仍保留在任务结果中。
6. 点击 Start 后，继续在原来的 Data → Harness → KB 画布查看真实进度；点击阶段或内部步骤查看输入输出，手动选择后可用“跟随执行”回到当前步骤。历史运行也使用同一张图，并读取其冻结方法。运行状态每 2.5 秒更新，流式输出由单独连接实时接收；新运行支持生成过程中阅读已收到的回答和服务提供的推理文本。浏览器断线后按序号续读已落盘的增量；部分输出不会被当作完整答案提交，旧非流式运行无法补出历史增量。
7. 在运行详情中暂停或恢复。暂停在当前模型调用或候选训练结束、收据落盘后生效。浏览器关闭不会终止工作进程。进程崩溃或已发送但未收到响应的任务保留为 interrupted/uncertain，禁止自动重发。

选题弹窗底部的“已选 N 题”可以打开完整已选列表，按选择顺序查看题目、打开详情或逐题移除，不受当前分类和分页影响。无法读取或不适用的已选版本仍显示在列表中，必须明确移除后才能应用。题库详情与选题预览使用同一阅读界面。

节点详情优先展示题目摘要、模型排序和判断理由，实际发送的角色指令、完整 Prompt、原始请求响应与配置可展开查看。程序节点读取经校验的历史产物；没有保存的输入输出会标为不可用，阶段事件不替代真实产物。查看记录不会触发新的模型调用。

每个节点先说明作用，再按该步骤展示结果：反馈节点对照模型首选与标准答案，候选指标用简表表示，已有的训练过程数据用带坐标与图例的曲线表示；假说、实验、知识库更新分别展示对应的结论和去向。没有记录的指标、排序方向或关联关系会明确说明，不自动猜测。哈希、文件路径、完整数字数组和原始 JSON 集中放在标注清楚的高级详情中。

Discoverer 使用明确的研究摘要：保留公开题面、已提交回答、候选最终均值与标准差、全部逐种子最终结果，以及原记录提供的筛选信息。完整训练曲线、环境字段和重复结果文件保留在封存的 `private_feedback.json`，不再拼进模型输入；摘要明确标记未提供的字段，来源冲突会停止执行。实际发送的摘要仍可在节点输入的高级详情中查看。

“研究材料太长”表示发送前的长度预检没有通过，模型尚未收到这一请求。预检仍按 UTF-8 字节数加输出预留和格式余量估算；很多题目、很多训练种子或很长的自定义指令仍可能超限。新错误会记录各项长度。旧运行使用原冻结输入、保留原状态；更新后需重新预览再提交新运行。

反馈表格下的“差距与重复训练波动”比较同一指标下的前两项，展示均值差和已记录训练的范围。只有方向、候选映射和完整逐次结果均可靠时才展示范围与逐次对照。它描述本题固定数据和预算下的表现，不把多次训练当成多个独立数据实例，也不把混合设置的排名解释成单个因素的因果结论。

## Task：新题解答与效果验证

Task 可单独选择已登记的 development/final 题集。独立评测分区为空时，选择器说明需先导入已划分的独立题包，不能直接将已生成的研究题当作最终盲测。开启后，研究使用 Data 的 discovery 部分（按轮数和每轮题数），Task 使用单独的评测题集；完整原始题集仍冻结在配置内。预览会说明实际参与和未参与的数量。未选择独立题集时，兼容使用原题集中已有的评测分区。关闭 Task 会保留选择，但不会执行评测。

服务端同时检查题目、数据实例、谱系与 DataFlip pair 是否与 Data 重叠；不将 discovery 题改名冒充新题。Task 比较同一个冻结模型在无 KB、初始 KB、本轮 KB 三个条件下的表现，显示正确题数、知识覆盖，以及相对无 KB 的答错变答对/答对变答错数。没有注入可用知识时不把分数差异解释为知识收益。Task 的答案与得分不反哺本轮 KB。

KB 列表区分候选、历史未验证、探索支持、独立确认和已退役知识。只有通过验证并启用的知识才标记可用于新题。流程执行完成可能仍没有知识变更，页面会显示实际保存的版本，不把完成状态当成知识有效性。

## 执行范围

在工作流选题列表中应用新的选择时，简化模式设为一轮、逐题回答全部所选题目，后续分析按最多四批分组；不会沿用旧的“只处理第一题”数量。该调整会在界面上明示。调用、token、训练和时间预算不会随选题数量自动提高，大批次仍受现有模型上下文与预算约束。高级设置中的多轮模式按冻结顺序分配不同题目，界面显示实际覆盖数量。打开旧草稿只迁移布局，不改变原有执行配置。

- 真实 LLM 调用和 GT 训练只允许在私有配置中指定的授权 Linux 服务器。本机可以浏览、编辑和运行无真实训练的测试。
- 原科学与配对 KB 研究固定一个模型配置及运行锁；独立评测支持多个已登记模型。修改模型配置产生新版本。
- v1 使用固定科学核心：Solver → 答案提交 → 反馈 → Discoverer → Skeptic → 实验 → Analyst → Curator → 证据校验/发布。独立确认和最终评估是可选路由。任意绕过提交、反馈或证据校验的连线会被拒绝。
- 提示词编辑是附加任务指令；角色权限、公开/私有数据边界与输出格式保持固定。模板预览与实际已发送请求分别标注。
- 最终评估要求题集中已有独立 dev/final split，并检查共享 dataset/pair lineage；本版不提供将历史发现题一键改成 held-out 题的按钮。
- 新题生成只使用 CPU、最多 200 次 candidate-seed runs。冻结批次不会根据中途结果自动换 seed。没有产出足够有效题时返回不足报告。
- 完整历史题包可以浏览；缺少必要 GT、数据绑定或配对来源的题目会显示原因并阻止执行。历史 KB 的未验证条目不能自动启用。

## 本地编辑服务

在本 worktree 根目录安装可选依赖，构建静态前端，然后启动 API：

```bash
python -m pip install -e '.[studio]'
npm --prefix frontend/workflow ci
npm --prefix frontend/workflow run build
PYTHONPATH=src python -m uvicorn services.kb_workflow_api.app:app --host 127.0.0.1 --port 8094
```

浏览器打开 `http://127.0.0.1:8094`。本机默认执行禁用。开发前端用 `npm --prefix frontend/workflow run dev`，端口 5174，API 默认代理到 8094，可通过 `STUDIO_API_TARGET` 改动。

## 服务器部署

部署目录由私有配置指定。独立 `.venv` 安装 API 依赖，以只读方式复用已有 CPU torch；不修改模型服务或其他项目虚拟环境。

`studio.env` 记录 `STUDIO_STATE_ROOT`、允许导入的 `STUDIO_SOURCE_ROOTS`、只读旧运行的 `STUDIO_ARCHIVES`、执行主机标识及监听端口。`ARCHITECTURE_IQ_KB_AUTHORIZED_HOST` 与 `ARCHITECTURE_IQ_KB_EXECUTION_HOST` 必须非空且完全匹配，系统必须为 Linux，否则真实执行禁用。服务默认只监听 localhost。

```bash
STUDIO_ENV_FILE=/absolute/path/to/private/studio.env bash tools/studio_server.sh
```

在本机私有 SSH 配置中为授权服务器设置 `studio-execution` 别名，再通过 SSH 转发访问：

```bash
ssh -N -L 127.0.0.1:8094:127.0.0.1:8094 studio-execution
```

导入指定的三个现有题目来源与模型运行锁：

```bash
PYTHONPATH=src python tools/studio_import_sources.py \
  --state /absolute/path/to/studio/state \
  --runtime-lock /absolute/path/to/studio/state/config/runtime-lock.json
```

详细导入报告写入 `state/import-report.json`。该脚本只读模型健康信息，不调用生成接口。

## 复现与状态

`state/` 包含 SQLite 题库索引、不可变题目与题集、模型修订、工作流版本和 `runs/{id}/`。
每个任务保留冻结配置、源码指纹、运行锁指纹、阶段事件、逐次调用收据与结果。
`/runs/preview` 返回 `config_hash`；提交 `/runs` 必须携带该值作为 `expected_config_hash`。
模型修订、题集、KB、源码或配置在预览后变化时，API 拒绝提交并要求重新预览。
源码或模型锁变化会拒绝执行已提交任务；不要覆盖正在执行任务使用的源码快照。
运行详情中的原始 JSON 是调试与复现的入口，完整文件仍在服务器产物目录中。

## 正常题 + DataFlip 题对（2026-10-10）

Data 中点击「选择研究题目对」，按类型或关键词浏览完整题对；「已选」页跨筛选与分页保留选择。详情列出实际数据变化、保持一致的候选配置、字母与候选身份对应关系，并分别阅读两题公开题面。选择器不提供标准答案。Task 也可选择独立 development/final 分区的题对。

Harness 支持两个成对协议：

- **题对对照**：先保存两题使用相同正式 KB 的独立回答，再对照真实反馈解释变化或不变。
- **渐进学习**：保留上述基线；只看正常题反馈形成待验证规律；使用该规律另做一次 DataFlip 迁移预测；最后揭示对照反馈并修订条件、例外、因素交互、竞争解释和下一步预测。

模型权重保持固定。归纳、迁移与修订分别封存，运行界面展示可读轨迹，精确提示词和实时返回仍在节点记录中。研究文字不是正式知识：只有合法假说通过原有审查、实验、确认与发布检查，才能进入正式 KB；Task 不读取待验证草稿。单题题集保持原协议；完整题对集必须使用成对协议，并按完整对分配轮次。

生成页选择「题目对」，提前冻结分区与因素值。首版通过 family 插件提供回归数据的 `domain`、二元序列数据的 `alpha`。同一对复用候选配置、预算与训练种子，只改变已登记因素。两侧均通过标准生成代码执行 GT、按相同候选子集进行显著性筛选；赢家不变的题对也会保留。请求数量按“对”计，预览显示双侧训练成本，实际生成量可能少于请求。

历史发布包的 250 对均涉及多个数据或采样变化，并经过赢家翻转筛选；可以用于对照研究，但不能作为单因素因果证据，也不能估计自然翻转率。新受控生成明确记录收录规则。Task 除共同答对率外，按候选身份报告赢家变化判断，避免选项字母重排造成假翻转。


## 论文方法与每轮决策（2026-10-10）

Harness 的方法选择器提供四个版本化配置：受控科学研究、渐进反事实学习、ExpeL 跨题经验学习、ExpeL × 反事实学习。选择方法后，内部步骤与题目模式同步改变，Data → Harness → KB 主结构保持固定。提交时冻结方法版本、模型、题集及配置；查看旧运行不会套用后来编辑的草稿。旧配置仍沿用原有协议。

ExpeL 选项是论文启发的改编：GLM 权重保持不变，先记录 discovery 中已提交答案和真实反馈，再整理跨题经验。后续轮次从先前经验中按公开特征检索案例和规律；实际使用的案例、规律版本及来源收据随请求保存。经验规律显示适用条件、例外、修订和来源，保持“待验证”身份。正式知识仍须通过已有受控实验和独立确认，模型的同意或经验重复不会提升其科学状态。

新建流程默认每轮结束等待选择：继续下一批、结束学习，或进入已配置的 Task。继续使用同一次运行预先冻结的下一批题；达到轮数上限后不再提供继续。可以选择有上限的自动循环，按轮数和连续无变化条件停止。人工等待不计入单轮工作时间，结束记录会绑定已完成轮次与知识版本。

Task 开启经验方法时，在无 KB、初始 KB、当前正式 KB 三组外，增加“当前正式 KB + 案例”“当前正式 KB + 经验规律”“当前正式 KB + 二者”三组，用同一冻结模型比较。评测不更新经验和知识；按题目、数据实例、谱系、题对排除重叠来源。比较结果说明提示材料的作用，不能据此声称模型权重学习或规律已获因果验证。

动画只随真实阶段事件改变。阶段状态约每 2.5 秒同步，模型增量通过独立 SSE 连接接收；未收到输出时显示等待，不生成模拟文本。详细收据、Prompt 和原始数据仍可展开，但默认画布只展示当前步骤、可读结果和本轮知识变化。

## RAG 作答

侧栏「RAG 作答」或题目详情的「用 RAG 匹配 KB 作答」可打开单题模式。选择题目、模型和知识条数（默认 8，最多 12），点击「匹配 KB 并预览」查看最多三个候选 KB、自动选用的第一名快照、匹配理由、来源版本和完整模型输入。题目只需具备有效公开输入，不依赖 GT；所有分区均可用于此研究练习，重复题目不属于独立评测。

当前策略 `public_features_text_v1` 使用公开规则条件、中文双字词项和英文标识符的 BM25 文本相关性，不调用 embedding 或额外模型。仅启用并验证适用的正式规则参与正式知识检索；经验来自同题型的封存案例，排除题目、数据集、谱系或配对标识相同的来源，经验仍标注为待验证。相同记录保留所有来源但只计一次；不同快照不混合。目录为空或没有适用知识时不能启动。

预览不调用模型。本地编辑模式允许检索预览；真实调用仅在授权执行服务器开启后可用。启动会重新检查题目、知识来源、模型版本和代码指纹，过期预览需重新匹配；只调用一次 Solver，知识按完整条目适配上下文预算。运行不计算 GT、评分或更新 KB，模型流式输出来自后端持久事件。历史详情区分提供的知识和模型实际引用，未知引用不会被解析为可信来源，失败或不确定调用保留实际收据且不自动重发。

# ArchitectureIQ Studio 研究工作空间设计

日期：2026-10-11

状态：用户已于 2026-10-11 确认本书面规格；按三个阶段分别细化实施计划。

## 目标与已确认的选择

让科研人员围绕 Data → Harness → KB → Task 管理研究材料、设计处理方法、积累知识并开展实验。四个模块各自专注自己的工作，使用一致的导航、排版和状态表达，采用适合内容的交互。

已确认的产品选择：

- Data 以多个命名 Dataset 为入口；Dataset 是题目集合，可以相互重叠。另有统一去重的总题库。
- 题目阅读采用做题式排版，支持选项交互和候选对比。第一版不增加人工作答提交和评分。
- 构题按数据类型显示对应的编辑块，复用真实生成能力。
- Harness 选择 Dataset，可以从模板或空白流程开始，自行增加、组合和连接处理步骤。
- 自定义处理采用提示词和内置节点；第一版不开放用户 Python、任意脚本或自定义工具 API 节点。已有模型 API 接入继续保留。
- KB 打开后默认阅读知识，切换到“适用题目”查看具体匹配关系。
- Task 仍在探索；本轮保留现有运行、RAG 作答、评测和结果查看能力，不增加新的任务或评分协议。
- 先用文字完善设计，不制作浏览器样稿。

成功标准是：新用户可以建立一个 Dataset、读懂其中一道题、组合并试跑一个 Harness、阅读产出的知识，再检查知识与其他题目的关系。高级科学方法、配对实验、来源与历史记录继续可用。

## 产品结构与范围

采用四个专门的工作空间：Data 的题库与构题编辑器、Harness 的流程画布、KB 的知识阅读器、Task 的既有执行和结果入口。模型登记放在公共设置中，在需要模型的节点内可以选择已登记配置。题源、导入和生成记录归入 Data。

单一四节点配置面板会使阅读题目、构题和读知识共享过于简单的模板；完全通用的自动化平台会引入本轮不需要的脚本、插件和外部集成。四个工作空间配合可组合的研究节点，作为本次选定方案。

初次进入展示 Dataset 库，后续恢复有效的导航位置。现有题目、RAG、工作流与运行链接保留兼容入口；打开旧工作流或旧运行时按其原版本展示。导航更新不转换旧草稿或修改已冻结的配置。

本轮不增加 embedding 服务、模型重排、自动语义去重、新的独立评测定义或人工答题评分。现有 BM25 和规则匹配继续如实标注。

## 共享对象与版本

| 对象 | 含义与约定 |
| --- | --- |
| 题目版本 | 现有不可变 question key/hash，包含明确的题面、候选、配置与来源关系。私有反馈保持隔离。 |
| 总题库 | 对题目版本建立统一检索和严格等价去重视图；保留原始记录和全部来源。 |
| Dataset | 用户命名的题目集合，具有稳定身份、名称、描述、当前修订和归档状态。内部使用 collection_id，与题内训练实例 dataset_id 区分。 |
| Dataset 修订 | 有序题目引用、选择模式以及显式题对成员关系的不可变快照。 |
| Harness | 可命名、保存和复用的处理方法，拥有可编辑草稿及不可变图修订。 |
| KB 与 KB 版本 | 命名知识库及其不可变内容清单；具体条目仍保留各自的产物类型、版本和证据状态。 |
| 运行 | 固定 Dataset 修订、有效题目顺序、Harness 图、模型配置、知识版本、预算与源码身份的一次执行。 |

编辑 Dataset、Harness 或 KB 的当前版本不改变已有运行。编辑请求携带基准修订；冲突时返回版本冲突并保留双方修改，不静默覆盖。

## Data

### Dataset 库和总题库

Data 首页以 Dataset 为内容单位，展示名称、用途、题量、数据类型构成和简短内容预览。搜索及类型筛选为辅助；一个 Dataset 可以包含多种类型。

新建 Dataset 可以为空。补充题目有三个来源：从总题库选入、导入题包、生成新题。导入来源与用户集合分别记录；同一来源可以服务多个 Dataset。生成成功的题目登记到总题库，并加入所选 Dataset 的新修订，实际失败和未收录记录留在生成历史中。如果生成期间目标 Dataset 被修改或归档，保留生成结果并提示重新选择加入位置，不覆盖集合或重复生成。

例如，Dataset A 包含 Q1/Q2/Q3，Dataset B 包含 Q2/Q3/Q4，总题库有四道题。Q2 在两个集合中引用同一内容；从 A 移除 Q2 不影响 B，也不删除总题库记录、来源或历史运行。

总题库作为 Data 内的统一搜索入口，显示每道题所属 Dataset、来源和版本。Dataset 中重复添加同一精确等价版本采用幂等处理。内容变化产生不同版本，界面保留版本区别。

### 去重边界

现有导入按原始题目 ID 与规范化记录 hash 识别重复。新增总题库的严格等价索引，支持不同展示 ID 的相同完整题目归为一组，但不替换原始 question key、冻结文件或历史引用。

等价策略单独版本化。首版仅忽略题目展示 ID 与导入管理字段，例如来源路径和导入时间；公开题面、候选顺序及候选身份、数据实例、谱系、配对身份、分区、生成与训练规格、公开代码、私有反馈及协议版本必须一致。参与比较的必要字段缺失或冲突时，保留不同记录。私有字段只在服务端用于一致性比较，不进入浏览、检索或模型输入。

相似措辞、相同题型、改换选项或数据种子都不足以自动合并。题对来源中的身份映射不同也保留区别。来源可用性继续按原记录核验，等价索引不能解除坏来源的限制。

总题库默认按等价题目版本计数；Dataset 成员仍保留明确的可追溯记录引用。新运行在预览时确定代表记录并冻结。任何重建等价索引的操作都不修改既有运行。

### Dataset 内浏览与读题

进入 Dataset 后可搜索、筛选、选题和翻题。题目摘要直接提供研究问题及关键条件；打开题目进入完整阅读页。

阅读页以题干、数据规则和候选方案为主体。点击选项有明确选中态，可将候选并排比较，高亮不同设置并折叠共同设置。代码、完整参数和溯源信息按需展开。保留上一题、下一题及加入题集等上下文操作。选择选项只是当前阅读交互，不生成答案收据或评分，也不提前展示 GT。

### 分块构题

构题编辑器按照以下内容分块，选择不同类型后只显示相应的有效字段：

1. 数据类型与生成规则。
2. 候选模型、优化器或损失配置。
3. 比较因素与固定条件；题对模式明确唯一的受控干预。
4. 训练预算与种子配置。
5. 生成规模、题目用途分区和目标 Dataset。

完成的配置块可以收成摘要，旁边预览构题规格和题面结构。实际题目和候选内容以真实生成结果为准。字段类型、单位、范围及兼容关系来自服务端能力清单；首版为现有支持的 family 补充明确表单 schema，不接受未知参数。

提交前沿用服务器预检与成本计算。真实生成继续执行 canonical 的 spec → generated code → execution → stored results，不增加第二套生成或训练逻辑。

### Dataset 作为实验输入

Dataset 可以收纳尚未完整或暂不适用的题目；运行预览按照具体节点与研究方法检查可用性。阻塞项定位到题目并解释原因，不能默默跳过。

选择整套、筛选或抽样后，预览固定 Dataset 修订、实际题目版本、顺序、抽样 seed 和完整题对成员。首版不允许筛选拆开已选择的研究题对。既有学习与科学方法通过适配层生成现有不可变 question_set；仅使用公开题面的自由图冻结自己的输入清单，不因缺少 GT 而拒绝原本可用的检索或文本处理。涉及反馈的节点仍要求该题具有完整且可核验的私有记录。

## Harness

### 编辑体验

Harness 是可复用的方法，可以更换 Dataset 或另存副本。创建时可选择已有方法模板，也可从空白图开始。主界面是画布；节点旁的加号和可收起的节点库用于添加步骤，支持连接、复制、删除、重命名和自动布局。

节点只显示名称、关键配置摘要和状态。选中节点时展开适合该步骤的编辑器，例如 Dataset 选择、知识检索配置或提示词编辑。模型提示词可插入上游字段，不要求用户编写 JSON 字段映射。高级技术标识放入详情。

连线展示材料名称，例如题目、命中知识、回答或经验草稿。系统根据端口类型推荐可连接步骤；多输入时明确每个字段来源。不存在的输入、错误类型或非法访问在对应节点和连线上解释。

### 第一版节点与产物

| 节点类别 | 行为与输入输出约定 |
| --- | --- |
| Dataset 输入 | 固定集合修订并输出题目集合，可配置筛选或抽样。 |
| 逐题或逐对处理 | 对固定顺序的题目或完整题对执行内部子图，输出有序结果集合。 |
| 字段整理与模板 | 在允许的字段内选择、组织结构化材料；操作为声明式配置，不执行用户脚本。 |
| 知识检索 | 接收公开题面和固定 KB 范围，返回匹配条目、来源与理由；不要求作答模型。 |
| 模型处理 | 可重复实例化，配置模型、指令、上游材料和受支持的文本或结构化输出格式。 |
| 作答与提交 | 对指定题目产生符合要求的回答，成功后封存答案收据；完整提交是读取反馈的前提。 |
| 对照反馈 | 引用该题、该次已提交回答，返回获准的真实反馈。 |
| 提炼经验 | 根据合法答案及反馈整理条件和例外，输出待验证经验；来源须通过专门适配器核验。 |
| 科学研究子流程 | 包装已有科学、配对或 canonical 实验能力，沿用其模型、输入及证据协议。 |
| 条件、合并、汇总 | 用声明式条件选择分支，合并已激活分支的输出，或汇总多题产物。 |
| 有界循环 | 配置最多轮数、显式循环状态和可选停止条件。 |
| 保存产物 | 根据产物类型保存研究记录、知识草稿、合法经验或经过证据检查的正式知识版本。 |

普通模型节点可以处理公开材料或其权限范围内的研究材料，其文本不能冒充答案提交收据。作答格式、来源验证和知识发布由程序节点承担。检索条目作为参考材料传入模型，不能赋予工具权限。

推荐起步模板为 Dataset → 逐题处理 → 作答与提交 → 对照反馈 → 提炼经验 → 保存 KB。另一个验收模板是同一道题进入两个不同提示词的独立作答分支，再汇总比较。用户可以插入中间处理步骤，执行确实随合法连接变化。

### 图执行语义

新增独立版本的 Harness 图和 Studio 调度器。节点具有独立实例 ID、节点类型与实现版本、参数和有类型的输入输出；同一类型可以多次出现。现有 workflow v1 继续按原科学协调器执行。

首版规则如下：

- 普通图是无环依赖图。迭代只能出现在显式的逐题、逐对或有界循环容器中，禁止隐式回边。
- 条件节点只使用受支持的比较、存在性及布尔组合，不执行表达式脚本。未选中的分支记录为 skipped。
- 汇合节点等待本次已激活的依赖；必需输入缺失会失败。收集顺序按冻结图和输入顺序确定，不取决于完成时间。
- 首版确定性串行调度就绪节点与题目；分支语义可用，不承诺并行加速。多个 KB 写入节点必须有明确版本依赖。
- 循环最多轮数为必填正整数，默认一轮，并受服务器能力上限及总调用、token、训练和时间预算约束。既有科研子流程保留其更严格的上限。
- 节点失败默认停止该次执行；逐题容器可显式选择记录失败并继续后续题目。汇总中列出失败和跳过项，不用替代输出补齐。

模型处理节点可以分别选择模型。科学或配对子流程保留其冻结模型和运行锁要求，不能通过外部节点配置改变其协议身份。

### 试跑与运行

编辑器支持配置检查、预览、单题或完整题对试跑，以及完整 Dataset 运行。配置检查与预览不调用模型；真实试跑仍只能在授权执行环境运行。

预览展示已经确定的输入、已固定资源和预算边界。依赖上游执行的材料标为“运行后确定”，不编造完整下游 Prompt 或输出。用户修改图、Dataset、模型或 KB 后需要刷新预览；运行提交校验同一冻结快照。

运行时画布显示真实节点状态，运行区域显示实际输入、输出、错误和用量。多题运行可以切换题目与迭代查看，保持选中的阅读位置。所有状态与文本来自持久化事件、收据或 SSE。

节点执行身份包含运行、节点实例、题目或题对、迭代和分支。重连读取已有事件；恢复复用已封存产物。已发送但结果不确定的调用不自动重发。暂停在可安全封存的执行边界生效，后台执行不依赖浏览器窗口持续打开。

### 答案与反馈边界

反馈节点必须引用同题、同次执行的有效答案收据。编译时明确独立作答阶段；若存在多个独立作答分支，必须先封存本次已激活分支的全部答案，再释放该题反馈。未激活的条件分支不参与等待，作答失败的题不能因此提前获得反馈。

反馈及其派生文本保留来源和访问限制，经过模板、模型、汇总或保存也不能去除标记。编译器和执行器共同阻止将反馈派生材料输送给尚未提交的独立 Solver。显式同题复盘可以使用先前经验，但必须标记为研究练习，不算独立评测。

题目、训练数据实例、谱系和题对的现有重叠检查继续生效。不同 Dataset 名称不构成数据独立性证明。

## KB

### 阅读为默认入口

KB 列表展示名称、用途、内容摘要、条目构成和当前版本。打开后进入固定版本的阅读页面，默认展示知识正文，目录用于定位条目。适用条件、例外、来源与验证状态紧随相关正文。

“适用题目”为可切换视图，返回阅读时保留版本、条目和阅读位置。切换版本必须明确，不因后台产生新知识而静默更换当前阅读内容。

### 知识类型与更新

不同产物共享可读的知识库入口，但保留独立的真实身份：

| 产物 | 保存与使用规则 |
| --- | --- |
| 研究记录或知识草稿 | 普通模型整理的文本，保存来源与权限标记；不进入自动 RAG 或独立 Task 的知识准入。 |
| 待验证经验 | 必须来自完整、可核验的答案反馈链；适配现有经验封存要求，不能以自由文本伪造来源。 |
| 正式知识 | 沿用 canonical 实验、已验证适用范围、规则及发布检查。 |
| 历史导入材料 | 保留原状态、来源与只读内容，不因迁移提升验证等级。 |

知识草稿采用独立产物类型，记录文本、可选条件与例外、来源引用、权限标记和内容版本。不得强行写入现有正式知识或封存经验格式。草稿可供有权限的研究整理节点读取，并保留原材料边界。

Harness 可新建 KB，或以用户选择的 KB 固定版本为基底生成新版本。默认保留原条目并添加新产物；条目修订和正式知识修改须通过对应类型的校验。并发更新发生基底版本冲突时报告冲突，不自动覆盖或混合。

KB 的逻辑身份与版本清单是新增管理层，引用真实知识快照及草稿产物。现有正式 KB、ExperienceStore 和历史快照的完整性规则保持有效；管理层不能重写底层证据状态。

### 适用题目

固定 KB 版本后，默认查询总题库的去重题目版本，可限定某个 Dataset 修订。每道题最多计一次，并显示所属 Dataset。结果列出命中的具体条目、候选组合或条件、匹配理由，以及知识验证状态。

明确区分：

- 来源题目：这条知识从哪里产生。
- 相关经验：公开条件或文本相关，尚未独立验证。
- 适用的正式规则：规则及已验证范围匹配了本题的特定候选组合。

匹配分数不是正确率；规则匹配不等于已经在这道新题上验证效果。草稿和未通过准入的正式主张可阅读、可搜索，不计入可用知识覆盖。经验检索继续排除同题、同数据实例、同谱系和同题对来源。

反向查询使用同一版本的准入、公开条件匹配和排名逻辑，但覆盖统计基于全体合格命中，不用模型请求的 top-k 或上下文裁剪结果代替。点击题目进入公开题面阅读，可对照匹配知识，不读取该题 GT。

展示查询总量、已检查量、可检查量、命中量，以及信息不足、来源异常等分类。全量检查完成后，覆盖比例采用“命中去重题目数 / 可检查去重题目数”，并说明分母。分母为零时显示暂无可计算范围；尚未检查的题不能显示为不适用。

查询缓存绑定 KB 内容、题库或 Dataset 指纹及策略版本，可重建且不入 Git。来源或内容变化后旧结果标为过期，不沿用旧统计。

### 匹配与作答分离

新增不要求模型的匹配操作，用于 KB 适用题目、Harness 检索和现有 RAG 页面。返回匹配产物及其来源指纹。用户进入作答请求预览时再选择生成模型，并按其上下文预算决定实际提供的完整知识条目。

作答预览绑定题目、匹配结果、模型修订和实际知识载荷。匹配来源变化需要重新预览。既有 RAG 接口保留兼容行为；新界面先匹配再预览。无相关知识可沿自定义流程中明确设置的无知识分支执行，但结果不能标作成功的 RAG 作答。

## Task 的本轮边界

Task 保留已有运行记录、RAG 作答和独立评测入口。执行 Harness 时可以留在当前画布看结果；Task 提供统一的历史查阅入口。Data 生成历史和 Harness 节点调试仍在各自工作空间内可达。

本轮不增加任务编排器，不重新定义评分，也不强制每次知识积累之后执行评测。科学和配对方法继续按现有固定协议运行，Task 的评测反馈不反哺正在被评测的 KB。

## 模块边界与接口

实现限于本仓库的 Studio、KB、API 和前端所有权范围。canonical 引擎提供既有训练、GT、规则及科学发布能力；新增编排层调用这些能力。

| 模块 | 职责 |
| --- | --- |
| Catalog 与 Dataset 服务 | 不可变题目、严格等价索引、集合修订、来源与运行输入冻结。 |
| Harness 注册与编译 | 方法身份、图修订、节点能力清单、类型和权限检查、预算与资源绑定。 |
| Harness 调度 | 按冻结依赖图执行、分支与迭代、产物身份、暂停和恢复。 |
| 节点适配器 | 模型 client、检索、受控科研子流程、答案反馈与知识产物的明确接口。 |
| 知识管理与匹配 | KB 版本清单、分级阅读、单题检索与反向适用性查询。 |
| JobStore 与事件 | 复用收据、幂等、真实输出、用量与失败持久化。 |
| 前端工作空间 | Dataset 浏览/读题/构题、Harness 画布、KB 阅读/适用题目、兼容 Task。 |

新增 API 按资源提供 Dataset 列表、详情、修订与归档，Harness 草稿、修订、验证、预览与提交，KB 逻辑身份、版本与适用题目查询，以及独立检索操作。接口统一使用服务端资源引用、版本守卫、结构化错误和分页，不能接受任意路径、客户端自报已验证状态或私有反馈正文。

旧 question-set、workflow、模型、运行和 RAG API 保持可读及既有调用兼容。新调度使用独立 schema/运行类型分派，不将 v1 图偷偷解释为可组合图。

## 迁移、错误与可访问性

已有题目、来源和 question_set 可登记为初始 Dataset 的引用，保留原记录与集合快照。迁移必须幂等；旧草稿和运行继续使用原身份及解析方式，不重写冻结 hash 来恢复运行。旧 KB 以只读版本适配进入阅读器。

空 Dataset、没有 KB、缺少模型、无合格匹配、来源损坏、版本冲突及超预算各自有明确状态和下一步操作。服务器执行未启用时，浏览和预览可用，真实运行显示执行环境状态。

题目阅读和 KB 正文使用合理行宽与可见层级；色彩主要表示类型、选中和状态。所有关键动作可用键盘完成，选项与节点具有可读名称。窄屏优先阅读内容，配置面板可独立展开；Harness 同时提供可访问的步骤导航，不能要求所有操作只能拖拽。

## 分阶段交付与验收

范围分成三个有明确边界的交付阶段，实施计划逐阶段细化；每阶段通过验证后再进入下一阶段，不把整个改造压成一次不可审查的提交。

### 第一阶段 Data 与共享资源契约

交付 Dataset 管理、总题库严格去重视图、题目阅读、分块构题及旧题集输入适配。约定后续 Harness 和 KB 共用的资源身份与修订接口。

- 两个 Dataset 可共享同一题；重复加入幂等，移除和归档不删除共享记录或来源。
- 跨展示 ID 的严格等价记录合并展示；配置、私有反馈或身份边界不一致时保留版本；近似题不自动合并。
- 集合修改不影响已经冻结的运行，完整题对和分区限制保持有效。
- 阅读页支持选项交互和真实候选差异比较，提交前不显示 GT。
- 构题字段与服务端能力一致，预检和生成仍调用 canonical 流水线。

### 第二阶段 Harness 编排与执行

交付内置节点、真实图编译/调度、模板、配置预览、单题试跑和批量追踪。新增草稿产物及 KB 版本写入契约。

- 空白流程可以增加同类型的两个节点，增加中间步骤或改变有效连接会改变实际输入与执行。
- 两路处理再汇总、条件跳过、逐题/逐对处理和有界循环均有确定的结果与顺序。
- 错误类型、缺失输入、非法循环、预算超限和反馈越界均在真实调用前或对应边界被拒绝。
- 独立作答分支完成提交前不释放反馈，派生文本不能洗掉权限标记。
- 节点输入输出对应真实收据和 SSE；不确定调用不自动重发，已完成调用恢复时不重复执行。
- 普通摘要不能发布为正式知识；合法经验与正式知识分别通过已有来源或证据检查。

### 第三阶段 KB 阅读与适用题目

交付 KB 阅读、版本选择、反向匹配、模型独立检索以及与 Dataset/Harness 的导航衔接。Task 保留既有能力。

- 打开 KB 默认阅读正文，切换适用题目再返回时保留版本和阅读位置。
- 单题匹配和覆盖查询采用同一准入策略，来源题目与可应用的新题分别呈现。
- 同一题跨 Dataset 只计一次；扫描未完成、信息不足和来源异常不被算作不适用。
- 匹配不需要生成模型；作答预览再绑定模型与上下文预算，过期资源使预览失效。
- 旧科学/配对方法、草稿、封存收据与历史运行保持原语义可读。

## 验证要求

实现和测试前核对仓库根目录，并使用准确的测试解释器验证 architecture_iq 导入来自本仓库 src/architecture_iq。后端执行使用 mocked 模型、虚拟节点和明确收据验证数据边界、图语义、版本守卫与恢复逻辑；前端以用户路径验证选择、编辑、导航、错误和实际事件渲染，再完成 TypeScript/Vite 构建。

验证同时覆盖旧科学与配对协议、现有模型 API、RAG 和历史运行兼容性。浏览器检查 Data 阅读/构题、Harness 连接与调试、KB 阅读切换、窄屏和键盘操作；不能访问实际界面时明确记录尚未完成的视觉验证。

真实模型调用及生成代码 GT 实验只在私有配置指定的授权 Linux 执行服务器进行，本地仅用于 UI、预览、构建与 mocked 测试。运行状态、源数据、凭据、模型权重和构建缓存不进入 Git。

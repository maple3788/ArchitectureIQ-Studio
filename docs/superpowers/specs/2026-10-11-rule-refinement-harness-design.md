# 结构化规则 KB 迭代 Harness 设计

日期：2026-10-11

状态：2026-10-11 用户已审阅并确认，明确接受不退步原则和建议停止条件。进入实施计划阶段，尚未开始实现。实施计划见 `../plans/2026-10-11-rule-refinement-harness.md`。

## 目标与已确认的选择

让科研人员通过已有题目和持续生成的新题，发现、检验和修订可执行的条件规则。KB 的使用可以脱离大模型：输入公开题目规格，程序匹配适用条件并预测候选优劣；大模型负责提出和修订规则。

用户已确认：

- 用程序直接执行结构化 KB，不逐题调用大模型作答。
- 在已有题和生成题上计算正确率，将错题交给大模型修订 KB。
- 规则冲突与错题一起进入修订环节，不投票、随机选择或调用模型强行补答案。
- 当前题池通过后生成新题；新批次失败时，自动纳入研究池，修订后继续生成另一批新题。
- 整个过程有运行限度，保留可以持续积累的规则及其适用边界。

产出是可执行、可追溯、可被反例修正的条件知识。有限题集通过不等于普遍真理，界面和报告说明实际验证范围。目标可以设为当前研究池全部通过，但不承诺一定收敛。

本设计细化总体研究工作空间中的一个 Harness 方法。保留 Data → Harness → KB → Task 的职责划分、可编辑流程与既有科学/配对方法，不把全部 Harness 固定成这个模板。

## 方案选择

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 每轮让模型重写整份 KB，再看整体正确率 | 编排简单 | 难以定位是哪条规则变好或退步，也容易丢失历史条件 |
| 每条规则独立版本与证据，模型提交修改，整库统一回归 | 可以解释反例、保留有效知识，并检验规则之间的冲突 | 需要明确规则合并、补丁验收和题池版本；本稿推荐 |
| 穷举条件或自动搜索规则，完全去掉模型修订 | 搜索过程确定，可做单独基线 | 需要另行定义搜索语言、复杂度和搜索预算，首版不扩展这一子系统 |

首版采用第二种。模型修订节点可编辑提示词和模型配置；确定性预测、评分和保存由程序节点完成。

术语中“候选对”指一道题内两个候选的比较；已有“题对”指正常题与反事实题两道完整题目。选择配对 Dataset 时保留完整题对及来源，分别预测和评分，并可汇总双题共同通过情况；不把这两种配对混为一谈。

## 最小闭环

```text
选择 Dataset + 初始 KB / 提出初始规则
                 ↓
固定 KB 和题池 → 执行规则并封存预测 → 对照 GT
                 ↓
        错题 / 冲突 / 缺口 / 规则反例
                 ↓
       大模型提出补丁 → 校验 → 全池回归
                 ↓
      接受改进版本，或保留原版并记录拒绝原因
                 ↓
       当前题池全部通过？否：继续修订
                 ↓ 是
       冻结构题方案 → 生成新题和真实 GT
                 ↓
     固定 KB 首次测试 → 保存首测成绩 → 纳入研究池
                 ↓
    有失败：继续修订；连续通过目标达到：保存并结束
```

任何阶段先检查剩余预算；达到限制、无法继续或用户停止时保存已完成产物与未解决问题。流程不依赖浏览器持续打开。

## 规则和 KB 的结构

参考用户提供的 `kb_v9_revision.json`、`kb_v10_revision.json` 的条件规则形式，以及本仓库的 `configs/kb_claim_rules/kb_0008_evidence_ge1.json`。参考目录仅用于设计阅读，不成为运行依赖。

一条规则包含：

| 内容 | 约定 |
| --- | --- |
| 身份与版本 | 稳定规则 ID、当前修订、父修订、增加/修改/拆分/合并/停用的关系 |
| 可读知识 | 一句条件性结论，以及边界与解释 |
| 可执行条件 | `scope`、`same`、`differ` 和 `predict`，沿用已支持的规则语言 |
| 适用与反例 | 命中的题目/候选对、预测方向、确定正确/确定错误/GT 未判定的记录 |
| 验证范围 | family、公开参数、预算、独立数据实例及测试批次；不能由模型自报验证成功 |
| 状态 | 候选、研究中、在指定批次通过、已停用；保持与既有正式科学验证状态分离 |

一条规则表达一个可单独检验的预测。导入历史条目的多条 clause 时保留父条目与 clause 来源，不能把局部可检验内容当作整段文字都已验证。

模型只能提出受支持的条件和操作，不能新增解释器字段、执行 Python、读取文件或更改 GT。题号、答案字母、来源路径和隐藏结果不能作为条件来记忆答案。缺失的公开字段不补猜测值。

KB 版本是规则修订列表的不可变快照。修改不覆盖旧版本；模型提案、接受版本、拒绝提案和原因都可查看。文本解释与可执行条件必须对应，实际预测以通过校验的条件为准。

这是新的研究规则产物，不能仅凭反复刷题通过就写成现有 `replicated_in_scope`，也不放宽正式 KB 的发布门槛。以后若要进入正式科学知识，仍走既有独立确认流程。

## 程序如何得到一道题的答案

首版预测目标为选出第一名，暂不要求输出所有候选的完整排序。

1. 从公开题目和候选规格提取已有白名单特征；固定特征提取器与规则解释器版本。
2. 对每一对候选运行所有适用规则，记录如 `A > B` 的有向关系及具体规则 ID。
3. 相同方向的重复关系合并证据，不按规则数量累计票数。
4. 任意候选对同时出现两个方向，或整题关系中出现有向环，都判为 KB 内部冲突；即使某个候选看起来能当第一名，也不出答案。
5. 没有冲突时，对同一道题、同一目标指标下的关系进行传递推理，例如 `A > B`、`B > C` 可以支持选择 A；保留完整规则路径，不把推导关系当作额外的独立验证证据。
6. 只有唯一候选能够沿这些关系胜过所有其他候选，才输出它。仍有多个无法区分的第一名或互不连通的候选组时，返回未覆盖或支持不足，列出尚未建立的比较关系。

关系只在同题、相同评价目标内合并，不跨题拼接胜负，也不把缺失关系当作平局。首版固定这一推理协议；以后更换合并策略须另立版本，不能改变历史成绩。

每道题输出预测或拒答状态、命中规则、比较关系及原因。先封存本批全部预测，再由评分器读取私有 GT。规则执行节点始终不读取真实答案；修订节点可以读取已经封存预测后的研究反馈。

预检要求所选题目具有可核验的评分材料；运行中来源健康状态或存储完整性变化时，报告资料故障并停止受影响的工作单元，不能把变化后的材料静默当作原冻结输入。

## 评分、问题清单与通过标准

整题与规则分别统计，不把候选对精度当成整题正确率。

- **整题正确率：** 正确题数 / 有有效 GT 的本批题数。冲突和未覆盖题保留在分母，作为未答对。
- **明确作答率：** 有唯一程序答案的题数 / 有有效 GT 的本批题数。
- **规则统计：** 适用候选对数、确定正确/错误断言数、未判定数、覆盖的数据实例与题目。
- **问题分类：** 答错、相反预测、循环偏好、未覆盖、无法区分候选、确定的规则反例、资料或执行失败。

整题对照现有存储答案评分。逐候选对的真值沿用 canonical 结果及现有明确胜负判据，不新增训练或 GT 算法。只有整题答案而缺少逐候选结果的历史题，可以计算整题成绩，但不能据此推断所有下位候选之间的真实关系。

GT 无法确定的候选对不计作规则错误，也不计为支持证据。GT 缺失、文件损坏、无法提取必要规格或任务执行失败单独报告，不能当作普通错题发给模型猜结果。记录选入数、可评分数和不可评分数；存在应完成而未完成的题时，本批不能显示全部通过。

**当前研究池全部通过：** 非空题池中全部题目完成且整题答对，冲突与未覆盖为零，所有当前活跃规则在本池上已确定的错误断言为零。没有命中过的规则保持未检验，不能借整库通过提升其证据状态。

即使一道题选对第一名，如果某条规则对下位候选作出了被 GT 明确否定的预测，也进入修订清单。

## 大模型修订与新版本验收

修订材料包括当前固定 KB、题池与分布摘要、所有问题的索引、分组代表案例、被命中的规则、预测与已揭示反馈，以及需要保留的正确行为。

大量案例超出上下文时，按问题类型、规则及 family 确定性分组和分批；记录实际送入模型的案例，不把只看了样本写成看过全部题。完整错误记录持久化，下一次修订优先补充尚未查看的类型。不能静默截断模型输入。

模型返回基于明确 KB 版本的补丁：增加、修改、拆分、合并、停用规则，并给出理由及案例引用。拆分与合并展开为可验证的条目操作，父子关系保留。模型不能修改数值结果、题池成员、评分标准或预算。

补丁处理依次为：结构与字段校验 → 生成候选版本 → 全研究池重新预测与评分 → 比较 → 接受或拒绝。

比较的两个版本必须使用同一个题池版本、题目/GT 引用及解释器版本。扩池后先得到旧 KB 在扩大题池上的基线，不拿小题池的 100% 与大题池的成绩直接比较。

已确认的首版验收策略：

- 已接受版本答对的题组成保护集合，新版本不得把这些题变成答错、冲突或未覆盖。拒绝提案曾经答对的题不加入保护集合。
- 首先比较正确题数；正确题数不变时，可以接受冲突题数减少，再比较确定错误规则断言减少，最后比较明确作答题数增加。
- 同分修补不允许明确作答题数下降；仅把错题改成未覆盖、清空 KB 或改措辞不算进展。
- 完全相同的可执行规则 hash 不触发重复全池计算，也不算改进。
- 每次接受后更新保护集合，保存前后变化，包括新改对、出现缺口和规则覆盖变化。

严格保护可能阻止需要暂时退步的修改。达到无进展限制时明确展示被拒提案与卡住的题，保存当前最好版本；不暗中改变验收策略。

## 新题、研究池与独立评测

初始研究池来自明确选择的 Dataset 修订；默认只接受研究用途的题目。生成挑战批次也使用研究用途，另外记录其在本次 Harness 中的状态：未测试 → 首次预测已封存 → 首次反馈已揭示 → 已纳入研究池。

挑战批次在查看本批 GT 前冻结生成范围、规格、seed 和规模，复用现有 canonical 生成过程。它可以依据以往反例选择希望探查的条件边界，但不能依据本批结果只保留容易通过的题。

每批新题先用未看过这批反馈的固定 KB 测试并保存首次成绩。随后整批加入研究池，包括当时答对的题；答对题进入保护集合，失败题和规则反例交给修订节点。题池扩充保留原 Dataset/题目版本，不把外部 Dataset 的并发编辑悄悄带进运行。

新题与旧题是否独立按题目、数据实例、谱系和题对身份检查，换题号或选项顺序不算新数据。需要新实例的生成协议遵守这些边界，重复结果登记但不计入独立新题数或连续通过批次，仍消耗生成尝试预算。生成完整题对时按双题和实际训练工作量预检，不拆对凑数量。

canonical 质量筛选、生成不足与失败如实保存：展示请求量、实际有效量和排除原因。不能通过无限补题或只留下有利结果达到目标。

已确认的默认成功条件为：累计研究池全部通过，且**同一 KB 版本连续两批新题首次通过**。任何 KB 修改使连续通过计数归零；需要的连续批次数可配置，至少一批。

保存所有批次的首测成绩及其 KB 版本，不能只展示最终通过的一批。重复生成后筛到通过的结果不标为独立无偏评测。

明确预留的 final 或独立 development 题不自动进入研究池，原有分区不改写。最终独立评测在 KB 冻结后通过 Task 执行，反馈不回流到这次 Harness。若以后将这些题用于学习，必须另开有明确研究用途记录的运行，不能继续把它们算作未见数据。

## 有界执行与恢复

“持续迭代”指可以接着已有 KB 和记录开始后续运行，每次运行本身有冻结的硬上限。

| 限度 | 已确认的首版默认值 |
| --- | --- |
| 最大修订尝试 | 默认 12 次；非法、重复、拒绝的提案也计数，另列接受次数 |
| 连续无改进 | 默认 3 次修订尝试，按上述验收策略判断 |
| 最多新题批次 | 默认 3 批；失败的生成尝试也消耗批次预算 |
| 每批目标题数 | 默认 16 道；生成不足不算完整通过 |
| 连续新批次通过目标 | 默认 2 批，同一 KB 版本 |
| 新增题目总数 | 默认最多 48 道；不限制已有研究池题数 |
| 模型调用、token、GT 工作量和总时长 | 必须填写正的累计上限，预检结合所选生成参数和服务器能力检查；未设置不能提交 |

真实生成可能为多道题共享数据实例与候选，因此 GT 预算按现有预检的 candidate × seed 工作量统计，不能用题目数代替训练成本。初始化、修订、构题中的真实调用、失败及被拒尝试都纳入对应总账。开始不可分割的工作单元前预留预算，余额不足时停止，不先超支再报告。

停止原因分别为目标达到、修订耗尽、新题批次耗尽、无进展、资源预算耗尽、用户停止、执行故障或结果不确定。只有目标达到才标为成功，其余情况返回当前最好 KB、真实成绩及未解决问题。

暂停与恢复按安全边界执行，复用已经封存的预测、评分、模型回执和生成结果，不重跑 GT。结果不确定的调用先核对已有回执，不自动重发。恢复不得重置预算或把旧运行换到新源码上继续。

## Harness 的界面

模板名建议为“规则发现与迭代”。研究者先配置四块内容：研究 Dataset、初始规则 KB、修订模型/提示词、新题方案与运行限制。

画布呈现输入、提出规则、程序验证、问题整理、模型修订、版本验收、新题挑战和保存节点。模型配置只出现在提出/修订以及确实调用模型的生成步骤，规则执行与评分节点不要求选择模型。

默认模板有清晰的内外循环容器，用户可以调整受支持节点、提示词与材料连接。反馈释放、预测封存、版本验收和预算边界属于后端协议，不能通过拖线绕开。首版仍不开放任意脚本。

运行页面以当前 KB、题池规模和实际问题数量为主体：

- 中间显示当前阶段及真实进度，顶部显示累计正确率、明确作答率和新题首测成绩。
- 问题区按错题、冲突、未覆盖和规则反例分组；点进后用已有读题样式展示候选与规则关系。
- KB 区直接阅读条件规则及修订差异，能查看一条规则命中的题、反例与证据范围。
- 时间线记录版本、扩池、新题首次成绩、接受/拒绝和停止原因；状态来自持久化事件/SSE。

本地可以配置、查看已有 KB、做不含真实调用的预览，以及对已存结果运行允许的确定性检查。真实模型调用与新题 GT 只在授权服务器执行。

## 与现有实现的关系

- 复用 Dataset 修订、输入冻结、Catalog 公开/私有边界和精确题目引用。
- 复用 `kb.rules.validate_rule`、`match_rule`、`public_views`，沿用现有候选对 GT 口径；不直接把历史宽松工具当作任意输入执行器。
- 新增整题关系合并、拒答原因和确定性预测收据。不能为填满旧 Solver 格式而随意补全排序，也不伪造模型回执。
- 新增研究规则 KB 版本、模型补丁、同池回归比较器、累计题池与批次使用账本、持久化有界控制器。
- 复用模型注册、调用预算/回执、JobStore、真实事件、已有生成服务和 canonical 引擎。
- 作为新的方法及运行协议分派，旧 scientific/paired/Basic/RAG、正式 KB 发布、草稿和历史 hash 保持原义。
- 运行所需模块和资源均在独立 Studio 仓库内。参考源目录只读，不增加跨仓库运行依赖。

## 验收要点

1. 规则执行不调用模型；GT 只能在本批预测封存后进入评分和研究反馈。
2. 相反关系、下位候选循环和无法区分第一名时均拒答；无冲突的传递推理记录完整路径，不重复计入规则证据。
3. 整题答对但存在确定规则反例时仍进入修订，GT 未判定不伪造错误或支持。
